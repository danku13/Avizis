# ADR-015 — Аудит использования токенов через событийный поток

> Статус: принято (CR-009) · Дата: 2026-10-12 · Связанное: [ADR-003](./ADR-003-event-sourcing-fold.md),
> [ADR-012](./ADR-012-byok-llm-router.md), [ADR-013](./ADR-013-truncation-audit.md), [FR-605](../fr/FR-600-history-and-log.md)

## Контекст

Прогон TACG делает серию LLM-вызовов четырьмя ролями (планировщик, исполнитель, супервайзер,
решатель), но пользователь нигде не видел, **сколько токенов** съедает каждый шаг и вся задача:
данные usage приходили от openai-compatible-провайдера (поле `usage` ответа) и терялись в
`chatText`, который возвращает только текст. Запрос пользователя (CR-009): «не вижу, чтобы в аудите
или где-то в интерфейсе выводилась информация о количестве затраченных токенов на вход/выход по
каждому шагу и в целом на всю задачу — нужно доработать».

Требования к решению: (1) захват usage у **обоих** адаптеров, включая zai; (2) атрибуция шагам
(узлам) и ролям; (3) видимость в live, в replay и в MD-отчёте — то есть **через событийный поток**,
а не только через снапшот; (4) честность: если провайдер не сообщает usage — не выдумывать цифры.

## Решение

**Usage — полноправное событие потока.** Каждый успешный LLM-вызов после аккумуляции в движке
порождает `RunEvent { type: 'llm:usage', role, nodeId?, inputTokens, outputTokens }`. Свёртка
`foldEvents` копит из него `RunView.usage` (totals + byRole + calls) и атрибутирует узлу
(`node.usage`), поэтому счётчики работают одинаково в live и в воспроизведении (до курсора),
а снапшот (`RunSnapshot.usage`) остаётся источником для персистентности (runs.json).

**Слои реализации:**

1. **Адаптеры (llm.ts).** `extractUsage` defensively читает `usage` ответа в форматах
   OpenAI (`prompt_tokens`/`completion_tokens`) и GLM (`input_tokens`/`output_tokens`).
   zai-адаптер возвращает usage, если SDK его сообщил; отсутствие usage — не ошибка.
   Новые функции `chatTextDetailed`/`chatJsonDetailed` возвращают `{ content/json, usage }`
   (для JSON-вызовов usage копится по всем попыткам парсинга); старые `chatText`/`chatJson` —
   тонкие обёртки, сигнатуры не менялись.
2. **Движок (engine.ts).** `addUsage(rt, role, usage, nodeId?)`: обновляет сводку снапшота
   (totals, byRole, calls), узел (`node.usage`, суммируется по повторным запускам) и эмитит
   событие. Исполнитель атрибутирует свой узел до финального `node:update` (usage попадает
   в событие и в инспектор); решатель атрибутирует узел-развилку; супервайзер и планировщик —
   только в сводку запуска (без записи в журнал — иначе шум после каждого шага).
3. **Журнал (аудит).** Записи шагов получают хвост `· токены: ↑N / ↓M` (только если провайдер
   сообщил usage); запись планировщика, финальная запись и summary запуска — итог
   `токены: ↑X / ↓Y (K вызов. LLM)`. Демо-режим без LLM не порождает записей о токенах.
4. **Фронтенд.** Чип в тулбаре (live и replay: `foldEvents` до курсора) с тултипом-разбивкой
   по ролям; строка «Токены: ↑ … · ↓ …» в мета-гриде инспектора узла; секция
   «## Использование токенов» (таблица по ролям + итог) и колонка «Токены ↑/↓» в таблице графа
   MD-отчёта.

## Альтернативы

- **Usage только в снапшоте** (без события): проще, но числа не работали бы в replay и
  «прыгали» бы при откате курсора — противоречит ADR-003 и требованию «по каждому шагу».
- **Кост-калькулятор в движке** (перевод в деньги): требует прайс-таблиц моделей и их версий —
  задел (см. «Последствия»), сейчас честные токены, а не выдуманные центы.
- **Отдельный kind журнала для токенов**: дал бы шум 7+ записей на прогон; вместо этого токены
  встроены в существующие смысловые записи (шаг/план/итог).

## Последствия

- Протокол событий расширен новым kind — старые прогоны (без llm:usage) совместимы:
  fold просто не найдёт таких событий, чип скрыт.
- `test-tacg-usage` фиксирует арифметику мока (7 вызовов = 700/140: planner 1 + executor 3 +
  supervisor 2 + decider 1) и совпадение fold ↔ снапшот ↔ runs.json; E2E проверяет чип, журнал,
  инспектор, MD и replay-уменьшение счётчиков.
- zai-адаптер может не сообщать usage — тогда чип/записи не появляются (провайдер не сказал —
  мы не придумываем). Это осознанное ограничение честного аудита.
- Задел поверх: стоимость в деньгах (прайс-таблицы), накопительная статистика по всем прогонам,
  тепловая карта токенов на графе (см. PRODUCT-001, H9).
