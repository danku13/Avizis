# ADR-016 — Динамический прайсинг моделей и аудит стоимости в USD

> Статус: принято (CR-011) · Дата: 2026-10-12 · Связанное: [ADR-015](./ADR-015-token-usage.md),
> [ADR-012](./ADR-012-byok-llm-router.md), [FR-908](../fr/FR-900-byok.md)

## Контекст

Аудит токенов (ADR-015) показывает вход/выход по шагам, ролям и итогу, но не отвечает на вопрос
«сколько это стоит в деньгах». Запрос пользователя (CR-011): «добавить стоимость в деньгах в плюс
к количеству токенов на базе прайсинга моделей (стоимости должны быть динамическими получаемыми
от провайдеров, а не захардкоженными)».

Ограничения задачи:

1. **Цены нельзя захардкодить** — они меняются у провайдеров, а набор моделей открыт (BYOK).
2. У провайдеров нет единого API цен: OpenAI и DeepSeek не публикуют машинно-читаемый прайс,
   OpenRouter публикует (`GET /api/v1/models`), индустриальным справочником служит открытый
   каталог LiteLLM (`model_prices_and_context_window.json`, 3000+ моделей).
3. Стоимости должны быть **честными**: неизвестная цена — «не оценено», а не выдуманное число;
   провайдер без прайса (z-ai SDK, локальный Ollama) не должен ломать подсчёт.
4. Аудит-модель уже есть: событийный поток `llm:usage` → fold → снапшот/инспектор/отчёт —
   стоимость обязана проходить тот же путь (live И replay).

## Решение

**Прайсы подтягиваются в рантайме из внешних источников, стоимость считается на стороне движка
и едет тем же событийным конвейером, что и токены.** В коде нет ни одной цифры цены.

**Источники (`pricing.ts`, приоритет по лестнице):**

| # | Источник | Что даёт | Особенность |
|---|---|---|---|
| 1 | `manual` — секция `pricing.models` в `data/llm-config.json` | цена конкретной модели, USD/1M in/out | приоритет выше сетевых; для z-ai SDK, Ollama, корпоративных тарифов; редактируется в UI (поля «Цена модели») и руками в файле |
| 2 | `openrouter` — `https://openrouter.ai/api/v1/models` | `pricing.prompt`/`pricing.completion` (USD за токен → ×1e6) | покрывает OpenRouter-конфиги: id совпадает точностью, включает наценку провайдера |
| 3 | `litellm` — открытый каталог LiteLLM (GitHub raw) | `input_cost_per_token`/`output_cost_per_token` | покрывает OpenAI, DeepSeek, Anthropic, Google и др.; де-факто индустриальный справочник |

Разрешение модели — лестница: точное совпадение (manual → OpenRouter → LiteLLM) → отброс
суффикса `:free`/`:beta` → базовый id (`openai/gpt-4o` → `gpt-4o`, LiteLLM) → OpenRouter по
базовому id **только при единственном вендоре** (неоднозначность → честное «нет цены», а не
случайная цифра). Всё best-effort: офлайн → прайсов нет, стоимость «н/д», прогон не страдает.

**Инфраструктура кэша.** Кэш в памяти (поиск синхронный — `addUsage` не становится async) +
`data/pricing-cache.json` (переживает рестарты). TTL по умолчанию 24 ч (`AVIZIS_PRICING_TTL_HOURS`);
`pricing.init()` при старте поднимает кэш с диска и фоном обновляет устаревшее;
`pricing:refresh` по сокету — принудительное обновление. `AVIZIS_PRICING_DISABLED=1` выключает
сетевые источники (air-gapped; остаётся manual). Таймаут фетча 12 с.

**Конвейер стоимости.** `addUsage` резолвит live-провайдера роли (`resolveRole` →
`providerInfoOf`) → `pricing.costFor(model, in, out)` → `costUsd = in/1e6 × priceIn + out/1e6 ×
priceOut`. Дальше симметрично токенам: событие `llm:usage` расширяется полями `adapter`, `model`,
`costUsd`, `priceSource` (старые прогоны без полей — совместимы); снапшот накапливает
`RunUsage.costUsd`, `byRole[role].costUsd` и `unpricedCalls` (вызовы без известной цены);
`node.usage.costUsd` — атрибуция узлу; fold на фронтенде суммирует то же самое → live и replay
честны. Журнал: хвост `· ≈$0,00045` у шагов, `· ≈$0,00315` в итогах; формат `fmtUsd`
(`$1,23` / `$0,0123` / `$0,00045` — 3 значащих цифры до $1, запятая).

**UI.** Чип тулбара: `↑ 700 · ↓ 140 · 7 вызов. · ≈$0,00315`; тултип — стоимость по ролям, при
отсутствии — «стоимость не оценена (N вызов. без прайса)». Инспектор узла:
`Токены: ↑ 100 · ↓ 20 · ≈$0,00045`. MD-отчёт: строка «Стоимость LLM», колонки «Стоимость»
в таблицах ролей и графа, блок provenance прайсов (источник — сколько моделей — когда обновлён —
кто без оценки). Модалка настроек: блок «Прайсинг моделей (динамический)» (статус источников,
кнопка «Обновить прайсы») и поля «Цена модели за 1M токенов, $» (manual override текущей
модели; пусто = каталог).

## Альтернативы

- **Захардкодить таблицу цен в коде:** прямо запрещено запросом; цены и модельные ряды
  провайдеров меняются, каталог устаревает за недели.
- **Считать стоимость на фронтенде по снапшоту:** ломает replay-честность и audit-трейл —
  цена на момент расчёта не фиксируется в прогоне. Считает движок, событие несёт готовую цифру.
- **OpenRouter Pricing API (`/api/v1/key/...`):** требует ключ и даёт цены только для аккаунта;
  публичный `/models` покрывает потребность без ключей.
- **Только LiteLLM:** OpenRouter-конфиги платят с наценкой провайдера — точное совпадение id
  с `/models` честнее для них; два источника взаимно страхуют офлайн/устаревание.

## Последствия

- **Позитив:** полный денежный аудит прогона (шаг → роль → итог) с фиксацией источника и
  свежести цены в отчёте; ноль захардкоженных цен; офлайн-деградация мягкая (токены остаются,
  стоимость честно «н/д»); manual override закрывает z-ai/Ollama/частные тарифы.
- **Негатив/риски:** каталоги — внешние зависимости (смягчено дисковым кэшем и TTL); цена на
  момент прогона фиксируется в событии, но refresh после прогона меняет цены для будущих вызовов
  (осознанно: событие хранит посчитанную цифру, а не прайс); entry-level кэши и OpenRouter
  наценка дают оценку «≈», а не биллинг (помечено в UI и отчётах).
- **Стоимость дополняет, но не заменяет токены:** unpricedCalls показывает покрытие прейскурантом;
  z-ai SDK без override — всегда «н/д».
