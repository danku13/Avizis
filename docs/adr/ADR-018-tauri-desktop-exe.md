# ADR-018 — Десктоп-упаковка Tauri: единый exe с UI, движок-sidecar

> Статус: принято (CR-012) · Дата: 2026-10-12 · Связанное: [ADR-017](./ADR-017-single-file-executable.md),
> [ADR-002](./ADR-002-socket-io-mini-service.md), [ADR-016](./ADR-016-dynamic-pricing-cost-audit.md), [FR-809](../fr/FR-800-clarity-agent.md)

## Контекст

Запрос пользователя (CR-012): «давай соберём на tauri единый exe с UI и сделаем сборку в github
с помощью github actions и сделаем первый релиз». ADR-017 закрыл уровень 1 (движок — один файл
`bun build --compile`) и наметил уровень 2 (UI рядом со статикой) и уровень 3 (Tauri). Настало
время уровня 3: desktop-приложение одним артефактом, который пользователь скачивает и запускает
без bun, без `next dev`, без ручного запуска движка.

Ограничения задачи:

1. **Единый exe**: пользователь получает один файл-установщик; UI и движок не требуют отдельных
   шагов запуска.
2. **UI вшит в приложение**: статический экспорт Next.js (`output: 'export'`), никакой внешней
   адресации — окно открывается мгновенно на встроенных активах.
3. **Движок — отдельный процесс**: bun-скомпилированный бинарник (ADR-017) с socket.io; встраивать
   его в Rust-процесс нереалистично (разные рантаймы), поэтому — sidecar-процесс с чётким
   жизненным циклом.
4. **Порт не должен конфликтовать**: 3003 может быть занят (dev-режим, второй инстанс) — оболочка
   выбирает свободный порт и сообщает его UI.
5. **Данные должны переживать переустановку** и не требовать прав записи в Program Files.
6. **CI**: сборка Windows в GitHub Actions, артефакт на каждый push, релиз по тегу; локально
   Rust-тулчейн в песочнице отсутствует — контракт должен быть проверяем без него.

## Решение

**Tauri v2 с externalBin-sidecar и initialization-скриптом: UI статичен и вшит в exe, движок
запускается оболочкой на свободном порту 127.0.0.1, порт инъекцируется в страницу до её загрузки.**

Конвейер (`.github/workflows/desktop.yml`, windows-latest):

```
bun install → bun build --compile (движок → avizis-engine-x86_64-pc-windows-msvc.exe)
→ AVIZIS_STATIC=1 next build (UI → out/, 1,7 МБ) → tauri build (Rust + NSIS-установщик)
→ артефакты: AVIZIS_0.10.0_x64-setup.exe + avizis-portable-windows-x64.zip
→ push тега v* → GitHub Release с release-notes.md
```

Разделение обязанностей:

| Компонент | Файл | Ответственность |
|---|---|---|
| Rust-оболочка (~130 строк) | `src-tauri/src/main.rs` | свободный порт; spawn sidecar с `AVIZIS_PORT`/`AVIZIS_BIND=127.0.0.1`/`AVIZIS_DATA_DIR`/`AVIZIS_CORS_ORIGINS`; initialization-скрипт `window.__AVIZIS_ENGINE_PORT__` до загрузки страницы; окно 1360×860 (мин. 1024×640); kill движка на `RunEvent::Exit` (без процессов-сирот); сток stdout/stderr в `app_log_dir()/avizis-engine.log` |
| Сайдкар | `src-tauri/binaries/avizis-engine-x86_64-pc-windows-msvc.exe` | `bun build --compile` — весь движок одним файлом (~94 МБ), см. ADR-017 |
| Конфиг Tauri | `src-tauri/tauri.conf.json` | `frontendDist: ../out`, `externalBin`, NSIS-бандл, WebView2 `downloadBootstrapper`; валиден по официальной схеме v2 |
| Движок | `mini-services/avizis-agent/index.ts` | `AVIZIS_PORT`/`AVIZIS_BIND`/`AVIZIS_CORS_ORIGINS` env — bind только localhost + точные origin'ы webview в десктопе (защита от drive-by подключений из браузера) |
| Данные | `data-dir.ts` | `AVIZIS_DATA_DIR` от оболочки → `%APPDATA%\ru.avizis.desktop` (переживает переустановку, не требует записи в Program Files); портативный exe-режим без оболочки — данные рядом с exe, как в ADR-017 |
| UI | `src/lib/avizis/socket.ts` | три режима подключения: инъекцированный порт (Tauri) → `?port=` (браузерная проверка контракта) → Caddy-шлюз (web) |

**Почему initialization-скрипт, а не query-параметр**: `WebviewUrl::App("index.html?port=N")`
полагается на то, как кастомный протокол резолвит query — поведение не документировано контрактом;
`initialization_script` гарантированно выполняется до любых скриптов страницы на каждой загрузке.
`?port=` сохранён как второй путь (E2E-контракт в браузере), Caddy-режим — как третий (web).

**Проверяемость без Rust-тулчейна**: десктоп-контракт = «статическая страница с портом движка +
движок на 127.0.0.1:port». Он проверен E2E в браузере (out/ на :8200 + движок :3155): подключение,
демо-прогон, LLM-прогон с валютой, консоль чистая. Rust-код сверен по исходникам tauri v2 и
tauri-plugin-shell (CommandChild/CommandEvent/sidecar-разрешение), конфиг — по JSON-схеме;
финальная компиляция — в CI (push → артефакт, тег → релиз).

## Альтернативы

- **UI раздаёт движок** (уровень 2 ADR-017): движок обслуживал бы статику — same-origin сокет,
  нет CORS вовсе; но UI перестаёт быть «вшитым в exe», а движок обрастает веб-сервером. Отклонено:
  против требования «единый exe с UI», Tauri-оболочка даёт нативное окно и инфраструктуру пакета.
- **Встроить движок в Rust-процесс**: разные рантаймы (Bun vs Rust), socket.io поверх FFI —
  недели работы без выгоды. Отклонено.
- **Фиксированный порт 3003**: конфликт с dev-режимом и параллельными запусками; статус «движок:
  недоступен» вместо диагностики. Отклонено в пользу свободного порта + инъекции.
- **tauri-action для релиза**: магия action'а против явных шагов (softprops/action-gh-release +
  upload-artifact) — выбраны явные шаги: меньше сюрпризов, релиз-ноты версионируются в репозитории.

## Последствия

- **Один установщик**: NSIS `AVIZIS_0.10.0_x64-setup.exe` содержит всё (UI, движок, иконки,
  WebView2-бутстраппер при отсутствии рантайма) — требования пользователя выполнены;
  `avizis-portable-windows-x64.zip` (оболочка + сайдкар) — для запуска без установки.
- **Подписи нет**: SmartScreen предупредит при первом запуске (честно указано в release-notes);
  апдейтер требует подписи и ключей — осознанно отложено.
- **NSIS ставит per-user** (`%LOCALAPPDATA%\Programs`), данные — в `%APPDATA%`: переустановка
  и обновление не трогают историю прогонов и BYOK-ключи.
- **Мак/Linux**: матрица CI расширяема (`darwin-x64/arm64`, bun кросс-компилирует сайдкар);
  первый релиз — Windows только (запрос «единый exe»); нюанс macOS — mixed content для
  `tauri://localhost` → http-сокета (решается `asset protocol`/http-доменом, задача будущих
  релизов).
- **Каждое окно = свой движок**: параллельные инстансы не мешают (разные порты, общий каталог
  данных с файловым замком от store). Ограничение зафиксировано в release-notes.
- **Статический экспорт наложил дисциплину**: убран мёртвый `/api`-роут; `AVIZIS_STATIC=1` —
  отдельный конфиг-режим next, web/dev-режим не изменился.
