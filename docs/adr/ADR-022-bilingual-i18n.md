# ADR-022 — Двуязычность RU/EN: язык интерфейса и язык прогона

> Статус: принято (CR-015) · Дата: 2026-10-13 · Связанное: [ADR-008](./ADR-008-demo-llm-dual-mode.md),
> [ADR-012](./ADR-012-byok-llm-router.md), [FR-710](../fr/FR-700-nfr.md)

## Контекст

Продукт двуязычен по аудитории: русскоязычный первичный сценарий и англоязычный (международный)
заход — для GitHub-релизов, демо и внешнего показа. До v0.11.0 весь текст (UI, словарь движка,
демо-сценарии, промпты, субтитры) был только русским.

Два независимых измерения языка:

1. **Язык интерфейса** — на каком языке разговаривает оболочка (кнопки, панели, модалки, ошибки
   конфигурации). Выбирает пользователь; по умолчанию — язык браузера.
2. **Язык прогона** — на каком языке агент думает и отвечает (план, названия узлов, выводы,
   вопросы развилок). Определяется **задачей**, а не интерфейсом: пользователь может вести
   UI на EN и вбить русскую задачу — агент обязан отвечать по-русски (и наоборот).

Оборванная сессия (контекст утерян, артефакты в коммите 48f6880) реализовала ядро: словари
RU/EN фронтенда, переключатель, локализованные системные промпты LLM, демо-видео с субтитрами.
Эта сессия завершила хвост: демо-контент оставался русским при EN-задаче, часть журналов и
ошибок движка была RU-only, поле задачи не следовало за языком UI.

## Решение

### 1. Интерфейс: плоские словари + zustand-стор, RU-пререндер

- `src/lib/tacg/i18n.ts` — стор (`locale`, `ready`, `init()`, `setLocale()`), `translate(locale,
  key, params)` с фолбэком **en → ru → ключ** и интерполяцией `{параметр}`; `useT()` — реактивный
  хук, `tNow()` — чтение языка стора на момент вызова (колбэки сокетов).
- Словари `i18n-ru.ts` / `i18n-en.ts` (~430 ключей): `history.*`, `toolbar.*`, `inspector.*`,
  `settings.*`, `decision.*`, `updater.*`, `report.*`, …
- **RU-пререндер**: статический экспорт рендерится с `locale='ru'`; сохранённый/определённый
  язык применяется после монтирования (`init()`), смена — текстовая, без всплеска (в отличие от
  темы CR-009, где класс `<html>` меняется до гидрации bootstrap-скриптом).
- Персист: localStorage `tacg-locale` + синхронизация `<html lang>`; дефолт — язык браузера
  (`ru*` → ru, прочие → en).
- Локаль UI уезжает движку в handshake socket.io (`?locale=`) — ошибки конфигурации и старта
  отвечаются на языке клиента.

### 2. Прогон: язык из задачи, один источник правды

- `mini-services/tacg-agent/i18n.ts` — `detectLang(task)` (кириллица → ru, иначе en), селектор
  строк `L(lang, ru, en)`, `promptLangSuffix(lang)` (EN-прогоны получают явное «Respond in
  English only: node titles, …, decision texts»).
- `rt.lang` фиксируется при старте и ведёт **весь** контент прогона: журналы всех видов,
  статусы/причины ошибок, адаптации, развилки (предложение/решение/гашение веток), заметки
  «понимания задачи», итоговый summary, ошибки управления API (override/retry/decision).
- **Демо-сценарии** — EN-зеркало `demo-i18n-en.ts` (идентичные id узлов и структуру, побайтово
  детерминированные тайминги): `demoPlan(lang)`, `demoWritingPlan(lang)`, `demoDecisionInsertions
  (lang)`, `demoAdaptations(lang)`, `demoAutoPick(lang)`, `demoWritingAutoPicks(lang)`,
  `demoInitialCertaintyNote(lang)`, `demoOutput(node, task, picks, lang)`; RU-контент остался
  в `demo.ts` как исходник.
- **Пустая задача демо** — дефолт на языке UI: `engine.start(..., uiLang)` ← locale из handshake;
  непустая задача всегда определяет язык сама.
- Промпты LLM: системные — RU/EN пары для всех четырёх ролей (PLANNER/EXECUTOR/SUPERVISOR/
  DECIDER `*_SYS_EN`), пользовательские шаблоны — RU + `promptLangSuffix` (суффикс требует
  английского ответа; проверено живыми EN-прогонами и демо-видео). Осознанное упрощение:
  пользовательские шаблоны не зеркалятся целиком — модели двуязычны, а инвариант «ответ на
  языке задачи» держит суффикс.

### 3. Стыковка UI ↔ прогон

- Поле задачи: `userTask = null` (пользователь не вводил) → показывается локализованный пример
  `history.defaultTask`, следующий за языком UI **при рендере** (без эффекта — ESL-правило
  setState-in-effect); любой ввод фиксирует владение полем за пользователем.
- Кавычки-ёлочки «» в сообщениях о выборе — RU, EN получает “curly” (по `rt.lang`).

### 4. Демо-видео

- `download/tacg-demo.mp4` — H.264 + две дорожки soft-subs (mov_text): `eng` (default) и `rus`;
  отдельные `.srt` рядом (внешние плееры, GitHub-релизы).
- `tacg-demo-preview.gif` — 12с-превью (рост графа супервайзером) для README.

## Альтернативы

- **i18next / react-intl** — тянут рантайм и слой конфигурации ради ~430 плоских ключей;
  отказано в пользу самописного `translate()` (нулевые зависимости, тривиальный фолбэк-контракт).
- **Единый язык прогона = язык UI** — ломает очевидный сценарий «EN-интерфейс, RU-задача»;
  отказано: язык прогона следует задаче.
- **Полный EN-зеркальный промпт-слой для пользователя** — дублирование ~200 строк шаблонов при
  равном результате (суффикс уже держит язык ответа); отложено до первых жалоб на качество EN-планов.
- **Вшитые (burned) субтитры** — конвертация видео под язык без переключения; soft-subs дают
  оба языка в одном файле.

## Последствия

- **+** Двуязычный продукт целиком: UI, прогоны, демо, видео; EN-аудитория получает
  англоязычный первый прогон (демо-режим по умолчанию).
- **+** Словари-зеркала демо: новая строка требует пары (RU, EN) — контракт виден в сигнатурах
  `L()`/функций-диспетчеров.
- **−** Промпты пользователя остаются RU-шаблонами + EN-суффикс (осознанное упрощение, см. выше).
- **−** Двойной объём демо-контента (~380 строк EN-зеркала) — цена сценарной симуляции;
  LLM-режим от этого не зависит.
