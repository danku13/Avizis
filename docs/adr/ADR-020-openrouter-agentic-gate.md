# ADR-020 — Обход гейта OpenRouter «agentic harnesses» для free-эндпоинтов

> Статус: принято (CR-013) · Дата: 2026-10-12 · Связанное: [ADR-012](./ADR-012-byok-llm-router.md),
> [ADR-016](./ADR-016-dynamic-pricing-cost-audit.md), [FR-911](../fr/FR-900-byok.md)

## Контекст

Запрос пользователя (CR-013): «надо заставить работать thinkingmachines/inkling:free, сейчас он
падает т.к. говорит что работает только с агентными приложениями».

Диагностика (живой каталог `openrouter.ai/api/v1/models` + страница модели): free-варианты
Thinking Machines Inkling принимают **только запросы агентных харнесов** — формулировка OpenRouter:
«The free Inkling endpoint is only available for use with agentic harnesses». Каталог подтверждает
механику: `supported_parameters` free-варианта содержит `tools`, но не `tool_choice` — признак
агентного запроса для гейта, при этом принудительный выбор инструмента не поддерживается. TACG
до этого слал чистый `chat/completions` без tools → 403 на каждом вызове (планировщик, исполнители,
супервайзер, решатель).

Сопутствующий дефект, вскрытый той же диагностикой: **4xx-ошибки провайдера гонялись всеми
ретраями** — планировщик делал до 5 запросов × 900 мс пауз, каждый узел ещё столько же; при
ключе/доступе, которые не «лечатся» повтором, прогон висел в «выполнении» минутами до терминальной
ошибки. Вместе с обновлением истории только по терминальному статусу (ADR-003, событийная модель)
это выглядело как «ничего не запустилось».

Ограничения:

1. **Нельзя всегда слать tools** — это меняет поведение обычных openai-compatible-провайдеров
   (модель может начать звать инструмент вместо прямого ответа); TACG работает с произвольным
   baseUrl, не только с OpenRouter.
2. **tool_choice не поддерживается** free-вариантом — нельзя принудить модель не вызывать
   инструмент.
3. **Прозрачность** —принцип TACG: вмешательство в запрос должно быть видимым и объяснимым,
   включая автоматическое добавление tools.
4. **Гейт может быть и не 403** — OpenRouter возвращает mid-stream ошибки и в теле 200-ответа.

## Решение

**Клиент openai-compatible вынесен в общий модуль `openai-client.ts` (используется и адаптером
llm.ts, и пробой валидации настроек). Первый запрос уходит без tools; если провайдер отвечает
ошибкой с маркером гейта (403-тело или `error` внутри 200), запрос повторяется один раз с
минимальным набором tools — `submit_final_answer` (одна функция «отправить итоговый текст»).
Решение кэшируется per `(baseUrl|model)` до рестарта движка — последующие запросы идут сразу
с tools, без лишнего 403.**

Ключевые детали:

| Аспект | Решение |
|---|---|
| Маркер гейта | `/agentic (harness\|application\|use case)\|only available for use with agentic/i` в теле ошибки (403/4xx) либо в `data.error` при 200 |
| Набор tools | одна функция `submit_final_answer{answer: string}` — харнесы всегда декларируют tools, этого достаточно; `tool_choice` НЕ шлём (free-вариант не поддерживает) |
| Ответ модели | `extractMessageContent`: `message.content`, при пустоте — аргументы `tool_calls` (поля `answer`/`result`/`output`, сырая строка, склейка нескольких вызовов) |
| Кэш | `Set<baseUrl\|model>` в памяти движка; сброс рестартом — самовосстановление при изменении поведения провайдера |
| Ретраи | 408/429/5xx — транзиентны (ретраятся уровнем llm.ts); прочие 4xx — `NonRetryableProviderError`, ретраи пропускаются, ошибка мгновенная |
| Валидация настроек | `validateProvider` идёт через тот же клиент: конфиг inkling:free проходит пробу и сохраняется (раньше сохранить было нельзя — проба падала в гейт) |

Альтернативы, отклонённые:

- **Всегда слать tools** — ломает поведение прочих провайдеров и моделей (см. ограничение 1).
- **Переключить гейт-модели на Responses API** — смена транспорта для частного случая провайдера,
  несовместима с «openai-compatible» контрактом BYOK.
- **Подменять заголовки/идентификацию приложения** — обман провайдера; TACG — действительно
  агентный харнес, честнее заявить это декларацией tools.

## Последствия

- inkling:free и другие gated free-эндпоинты работают в LLM-режиме «из коробки»: первый вызов
  платит один 403, дальше — кэш (перезапуск движка пере-детектит за один запрос).
- Модели, отвечающие вызовом `submit_final_answer`, разворачиваются в текст тем же пайплайном
  (JSON-ремонт ADR-001 применяется к извлечённому тексту).
- 4xx-сбои ключа/доступа теперь фейлят прогон за секунды (было: минуты ретраев) — журнал сразу
  показывает человеческую причину (FR-906).
- Поведение остальных провайдеров не изменилось: без маркера гейта запросы идентичны прежним
  (регрессии byok/usage/pricing — без изменений).
