# ADR-019 — Конвертация валюты для стоимости прогонов

> Статус: принято (CR-012) · Дата: 2026-10-12 · Связанное: [ADR-016](./ADR-016-dynamic-pricing-cost-audit.md),
> [ADR-018](./ADR-018-tauri-desktop-exe.md), [FR-910](../fr/FR-900-byok.md)

## Контекст

Запрос пользователя (CR-012): «добавим конвертацию в валюту через запрос к какому-то бесплатному
api (точно данные можно получать в ЦБ, возможно есть смысл взять несколько точек откуда можно
получать курс для конвертации)». Аудит стоимости (ADR-016) ведётся в USD; для пользователя
в России (и не только) естественна цена в рублях — да и в других валютах при BYOK-провайдерах
из разных юрисдикций.

Ограничения задачи:

1. **Курсы нельзя захардкодить** — тот же принцип, что и с ценами моделей (ADR-016): цифры
   меняются ежедневно, набор валют открыт.
2. **ЦБ РФ не даёт JSON**: официальный `XML_daily.asp` — XML в windows-1251 с запятой в дробях
   и номиналами ≠ 1 (100 KZT, 100 JPY); нужен парсер и честная обработка кодировки.
3. **Один источник — одна точка отказа**: сайт ЦБ бывает недоступен/медленный; пользователь
   явно предложил «несколько точек» — цепочка фолбэков.
4. **Базис аудита — USD**: события `llm:usage` и runs.json не должны зависеть от курса (курс
   меняется каждый день — исторические прогоны нельзя «пересчитывать задним числом»); конвертация
   — слой отображения.
5. **Офлайн и детерминизм**: без сети стоимость остаётся в USD; тесты требуют воспроизводимости
   (ручной курс).

## Решение

**Курсы подтягиваются в рантайме из цепочки источников и кэшируются на диске; конвертация
происходит только на отображении (чип/тултип/инспектор/MD-отчёт), событийный поток и снапшоты
остаются в USD.**

Источники (`currency.ts`, приоритет **по каждой валюте**):

| # | Источник | Формат | Особенность |
|---|---|---|---|
| 1 | `manual` — секция `currency.rates` в `data/llm-config.json` | число: единиц валюты за 1 USD | детерминированные тесты, офлайн-работа, свой курс; редактируется в UI (поле «Ручной курс») |
| 2 | `cbr` — официальный XML ЦБ РФ `www.cbr.ru/scripts/XML_daily.asp` | XML, windows-1251 | прямой USD→RUB, остальные — кросс через рубль с учётом Nominal; дата реестра → `asOf` |
| 3 | `cbr-mirror` — `www.cbr-xml-daily.ru/daily_json.js` | JSON-зеркало ЦБ | те же курсы без XML-парсинга; обход таймаутов основного сайта |
| 4 | `er-api` — `open.er-api.com/v6/latest/USD` | JSON | независимая точка: ~160 валют напрямую за 1 USD, без ключа |

Валюты — куррируемый список из 15 (USD/EUR/RUB/KZT/CNY/GBP/TRY/AED/INR/BYN/UAH/GEL/JPY/CHF/KRW):
все есть у ЦБ (кроме RUB-базы и USD) и у er-api. Кэш — `data/currency-cache.json`, TTL 6 ч
(источники обновляются раз в день; `TACG_CURRENCY_TTL_HOURS`), `TACG_CURRENCY_DISABLED=1` —
только ручной курс, `TACG_CURRENCY_URL_*` — подмена URL для тестов. Всё best-effort: офлайн →
конвертации нет, стоимость в USD, прогон не страдает.

**Паттерны наследованы от прайсинга (ADR-016)**: инъекция fetcher'а в тесты, per-key merge
ручных курсов при сохранении конфига, санитайз (коды A-Z{3}, числа > 0, ≤ 20 записей),
`publicConfig` отдаёт курсы (не секретны), сокеты `currency:status`/`currency:get`/
`currency:refresh` + broadcast статуса после обновления.

**Слой отображения**: движок эмитит только `costUsd`; UI конвертирует на лету (`convertUsd`/
`fmtCurrency`, 3 значащих цифры — согласовано с `fmtUsd`): чип тулбара («· ≈$0,0027 · ₽0,263»),
тултип по ролям, строка узла в инспекторе, MD-отчёт (колонки ролей/графа + блок «Курс
конвертации» с источником и датой котировки). Валюта выбирается в настройках (дефолт ₽),
выбор живёт в `localStorage 'tacg-currency'`.

## Альтернативы

- **Конвертировать в движке и эмитить costRub**: событийный поток привязан к курсу дня запуска;
   replay показывал бы другую сумму при смене курса; исторические прогоны «плыли» бы при каждом
   обновлении курсов. Отклонено: конвертация — только на отображении, базис USD неизменен.
- **Только ЦБ (один источник)**: единая точка отказа (сайт ЦБ периодически недоступен,
   geo-блокировки). Отклонено: три сетевых источника + ручной курс.
- **Все ~160 валют er-api**: список в UI нечитаем, 99% не нужны. Отклонено: куррируемый набор 15
   (расширение — правкой массива SUPPORTED_CURRENCIES).
- **CBRF через XML-библиотеку**: зависимость ради 40 строк регексов на ASCII-полях
   (CharCode/Nominal/Value) — избыточно; cp1251-декод нужен только для честности декодирования,
   парсинг от него не зависит.

## Последствия

- Чип/инспектор/отчёт показывают честную пару «$ + валюта» с источником курса и датой котировки
  (аудит-требование: provenance каждой цифры).
- Ручной курс в конфиге = офлайн-режим и воспроизводимые E2E (как manual-прайс для моделей).
- Свежесть курсов — отдельная от цен моделей ось: прайсы TTL 24 ч, курсы 6 ч; блоки в настройках
  соседствуют, но обновляются независимо.
- `asOf` источников (дата реестра ЦБ) ≠ времени загрузки — в статусе различаются и то, и другое.
