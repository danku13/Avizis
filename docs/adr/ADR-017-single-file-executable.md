# ADR-017 — Упаковка стенда в исполняемые файлы (Windows/macOS, «один файл»)

> Статус: принято (CR-011; агенты — проверено сборкой и запуском) · Дата: 2026-10-12 ·
> Связанное: [ADR-002](./ADR-002-socket-io-mini-service.md), [tech-stack](./tech-stack.md)

## Контекст

Запрос пользователя (CR-011): «как минимальными усилиями обернуть сервис в windows / macos
executable для запуска "одним файлом" без развёртывания инфраструктуры». Стенд состоит из двух
частей: мини-сервис движка (bun + socket.io, `mini-services/avizis-agent`) и фронтенд Next.js
(`next dev`/`standalone` + Caddy-прокси на :81). Для «продуктового» запуска нужна связка без
Node-инструментария, без `bun install`, без Caddy — Ideally один файл на каждую ОС.

## Решение

**Многоуровневая стратегия — от проверенного сегодня к полному «одному файлу».**

### Уровень 1 — «один файл на движок» (реализовано и проверено в этой сессии)

`bun build index.ts --compile --target=bun-<os>-<arch>` — кросс-компиляция с любой платформы
без тулчейна целевой ОС. Скрипт [`scripts/build-executables.sh`](../../scripts/build-executables.sh)
собирает 4 таргета (windows-x64, darwin-x64, darwin-arm64, linux-x64; при желании + arm64-варианты):

```bash
bash scripts/build-executables.sh          # → mini-services/avizis-agent/dist/avizis-agent-*
```

Проверено: бинарник (62–95 МБ: рантайм Bun + socket.io + адаптеры LLM вшиты внутрь) стартует,
обслуживает socket.io, тянет прайсы из сети. **Портативные данные** (`data-dir.ts`): в
скомпилированном бинарнике `import.meta.dir` указывает в виртуальную read-only ФС `/$bunfs/root`,
поэтому `data/` (runs.json, llm-config.json, кэш прайсов) переносится в каталог рядом с exe —
переносимость копированием одного файла (+ при желании папки data с историей).

Фронтенд на этом уровне — вторым артефактом: `bun run build` → `.next/standalone` (включая
`node_modules`, ~десятки МБ) + `bun .next/standalone/server.js`; UI ходит на :3003 напрямую
(сокет-клиент уже умеет `XTransformPort`-проксирование, а локально прокси не нужен). Итог
уровня 1: **zip из exe + standalone** (2 сущности), запускается двойным кликом по `.bat`/`.sh`.

### Уровень 2 — «один файл совсем» (рецепт, задел)

Движок и UI склеиваются в один бинарник: Next.js переводится на статический экспорт
(`output: 'export'` — приложение одностаничное и клиентское, серверных маршрутов нет),
`out/` встраивается в исполняемый файл (Bun embeds директории как ассеты), и один процесс
обслуживает и статику (`Bun.serve({ static: ... })`), и socket.io на том же порту. Изменения:
(1) `next.config.ts` → `output: 'export'` (проверить, что нет `next/image` без лоадера и
динамических SSR-маршрутов); (2) socket-клиент: при same-origin не добавлять `XTransformPort`,
ходить в свой origin; (3) входная точка-сервер ~40 строк (Bun.serve + существующий io). Тогда
`avizis-app.exe` = один файл: открыл браузер на `http://localhost:3003` — всё работает.

### Уровень 3 — «настольное приложение» (опционально, по запросу рынка)

Нативное окно без браузера: **Tauri v2** (сайдкаром уровня 2, системный webview, ~5–10 МБ
обёртки) или Electron portable (проще, но ~100+ МБ). Для прототипа не нужно; выбирается по
сигналу от ЦА (см. PRODUCT-001: С1/С3 переносят стенд на машины клиентов).

## Альтернативы

- **Node.js SEA / pkg:** SEA экспериментален и не умеет паковать директории ассетов Next.js;
  pkg заморожен upstream — оба хуже Bun compile для bun-native кода.
- **Docker:** «без развёртывания инфраструктуры» прямо исключено запросом (Docker Desktop —
  та же инфраструктура).
- **deno compile:** рабочий аналог, но код уже bun-first (`import.meta.dir`, Bun-скрипты),
  двойной рантайм не оправдан.

## Последствия

- Уровень 1 доступен сейчас: кросс-сборка из репозитория, артефакты в `dist/` (gitignored),
  данные рядом с exe. Ограничение: z-ai-адаптер рассчитан на окружение стенда — в «полевых»
  exe рассчитывайте на openai-compatible (BYOK).
- Уровень 2 требует миграции конфигурации Next.js и сокет-клиента — задел, оценивается в
  полдня работы; риски: React Flow/тяжёлые ассеты в статике (кэшируются — ок), потеря dev-режима
  Next (для продукта не нужна).
- Уровень 3 добавляет нативный тулчейн (Tauri — Rust) — сознательно отложено.
