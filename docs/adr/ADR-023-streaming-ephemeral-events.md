# ADR-023 — Стриминг выхода как эфемерные события (вне журнала запуска)

> Статус: принято (CR-016) · Дата: 2026-10-21 · Связанные: [ADR-003](./ADR-003-event-sourcing-fold.md)
> (event sourcing), [ADR-012](./ADR-012-byok-llm-router.md) (роутер LLM), [ADR-015](./ADR-015-token-usage.md)
> (usage), [FR-907](../fr/FR-900-byok.md)

## Контекст

Стриминг выхода исполнителя (узел «пишет на глазах») требует доставки частичного
текста в UI во время выполнения шага. Событийная модель (ADR-003) пишет каждый
шаг в `RunEvent[]` запуска: `node:update` на старте/финале, `llm:usage` на вызове,
журнал `log`. Наивное решение — пушить каждую дельту стрима как обычное событие
через `emitEvent` — имеет цену: сотни событий на прогон раздувают `runs.json`
(урезается до `MAX_RUNS`), журнал/таймлайн замусориваются, replay обязан
воспроизводить то, что для аудита — шум.

## Решение

`node:stream` — **эфемерное событие-снапшот**, живущее только в socket-канале:

1. **Снапшот, не дельта**: `text` — весь накопленный текст на момент эмита.
   Клиенту не нужно копить состояние; любая потерянная посылка лечится
   следующей; стрим нельзя «испортить» порядком доставки.
2. **Мимо журнала**: движок эмитит напрямую через socket (`run:event`),
   минуя `emitEvent` — событие не попадает в `events[]` запуска и в `runs.json`.
   Аудит-трейл (MD-отчёт, журнал, токены/стоимость) и семантика replay
   не меняются: для истории шаг по-прежнему «старт → финал с полным output».
3. **Троттлинг ~350 мс на узел + обязательный flush** перед `node:update(done)`:
   верхняя граница эфемерного трафика (~3–8 событий на шаг), финальный снапшот
   не теряется, UI не мигает между «последним снапшотом» и «готовым output».
4. **Клиент затирает**: `streamingText` живёт на узле только до следующего
   `node:update` (running→done/error); в replay-потоке `node:stream` не
   встречается вовсе, фолд толерантен к его отсутствию.

## Последствия

- Свёртка детерминирована: финальное состояние не зависит от стрим-событий
  (покрыто тестом A3 в `test-tacg-stream.ts`).
- Стрим — UX-транспорт, а не семантика запуска: fallback стриминга на полный
  вызов (llm.ts) ничего не меняет в аудите.
- Если в будущем захотим replay-анимацию «наблюдаемого набора текста» —
  снапшоты можно персистить отдельным lane'ом (sidecar), не смешивая с
  каноническими событиями; текущее решение этого не блокирует.
