# ADR-014: Вычислимая метрика понимания вместо самооценки LLM

> Тип: ADR · Статус: **задел** (⬜ не реализовано; направление зафиксировано по запросу
> пользователя: «опиши в документацию на будущее») · Связанное:
> [ADR-009](./ADR-009-mixed-selection-certainty.md), [FR-805](../fr/FR-800-clarity-agent.md),
> [FR-810](../fr/FR-800-clarity-agent.md)

**Контекст.** Метр «Понимание задачи» (certainty, 0..1) сегодня — **самооценка LLM** из трёх
источников: планировщик при старте (промпт-ориентир «размытый → 0.2–0.4, конкретный → 0.6–0.8»),
`certaintyAfter` при закрытии вопросов, супервайзер после шагов (при |Δ|>0.05). Свойства и
слабости: значение не откалибровано и не связано формулой с состоянием графа; решения обновляют
его монотонно (`max(cur, after)`), супервайзер может снижать — семантика смешанная; пороги шкалы
«Размытый вектор / Вектор сужается / Узкий вектор» (0.35 / 0.7) и эвристики (+0.15, ≤0.95) —
магические числа. Одинаковые состояния графа могут давать разные оценки; разным состояниям —
одну и ту же.

**Предлагаемое решение (направление).**
1. **Источник истины — наблюдаемое состояние графа**, а не самоотчёт модели:
   - `R` — множество релевантных доменов задачи: планировщик помечает при старте подмножество
     из 8 (scope, specialization, product, architecture, tone, format, context, strategy);
   - `C(R)` — закрытые домены (вопросы с `resolved`-решением);
   - `O` — открытые уточнения (развилки в статусе `offered`);
   - `W` — ширина активного пространства решений: по каждой открытой развилке — число активных
     (не `discarded`) вариантов; свёртка — произведение по развилкам (или `log2`, чтобы не
     взрывалось);
   - `B` — доля погашенных веток (`discarded`) от всех созданных.
2. **Формула-кандидат**: `computed = 1 − (Σ w_d · open_d / Σ w_d) · shrink(W)`, где `w_d` — вес
   домена (product/architecture выше: цена ошибки больше), `open_d ∈ {0,1}` открыт ли домен,
   `shrink(W) = 1 / (1 + log2 W)` — монотонная убывающая функция ширины. Достоинство:
   разложимость — вклад каждого домена и каждой развилки виден и показуем в UI.
3. **Гибрид на переходный период**: `displayed = clamp(α·computed + (1−α)·selfReport)`, α растёт
   к концу прогона: самооценка полезна рано (граф пуст, формуле нечем считать), вычислимая
   метрика — поздно (граф богат состоянием).
4. **Метрики качества перехода**: стабильность на повторных прогонах одной задачи (дисперсия),
   корреляция с числом override/retry (прокси ошибок понимания), калибровка порогов шкалы
   по этим же данным (вместо магических 0.35/0.7).
5. **Миграция**: этап 1 — параллельный расчёт `computedCertainty` рядом с certainty (оба поля в
   событии `run:certainty`, UI переключается флагом); этап 2 — A/B на демо-сценариях
   («данные» / «Напиши пост»); этап 3 — computed становится основным значением метра, самооценка
   остаётся отдельным рядом «уверенность агента» (полезна как сигнал калибровки модели).

**Открытые вопросы.** Учёт mixed-решений (домен закрыт частично — нужен дробный `open_d`, а не
0/1); веса доменов — фиксированные константы или подбираемые; судьба `certaintyAfter` от
планировщика (использовать как prior в гибриде); обучение порогов шкалы на накопленных прогонах.

**Последствия (если реализовать).** Метрика становится воспроизводимой (одно состояние графа →
одна оценка), объяснимой (разложение по доменам и веткам выводится в инспектор), тестируемой
(юнит-тесты формулы на фиксированных графах). Цена: зависимость от качества разметки релевантных
доменов планировщиком (само это мета-решение — снова LLM, но проверяемое в аудите), усложнение
fold и UI, рост объёма снапшота.
