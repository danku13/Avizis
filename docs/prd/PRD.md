# PRD — Avizis Playground (Transparent Agent Computation Graph)

> Тип: PRD · Версия: 0.4 · Статус: реализовано (прототип для тестирования концепции) · Язык интерфейса: русский
>
> Ссылки: [требования](../fr/index.md) · [решения](../adr/index.md) · [журнал изменений](../cr/index.md)

## 1. Проблема

Современные LLM-агенты выполняют задачи «чёрным ящиком»: пользователь видит финальный ответ,
но не видит, *как* агент рассуждал, какие шаги предпринял, где поменял план, где принял
ключевое решение — и не может вмешаться до того, как ошибка распространится на весь downstream.

## 2. Продукт

**Avizis Playground** — интерактивный стенд, где агент (на `z-ai-web-dev-sdk`) выполняет задачу,
а пользователь наблюдает вычисления в виде **живого графа**:

- агент **планирует** шаги → план становится DAG-графом;
- агент **выполняет** шаги → узлы загораются, рёбра анимируются;
- агент **адаптирует план** → появляются новые узлы и версии графа (v1 → v2 → v3);
- агент доходит до **развилки решений** → предлагает варианты с обоснованием и превью шагов;
- пользователь может **вмешаться**: поставить на паузу, переопределить результат узла,
  повторить узел, выбрать вариант решения;
- всё фиксируется в **событийном потоке** → любой прогон можно воспроизвести покадрово
  и экспортировать как MD-отчёт аудита.

## 3. Цели и не-цели

**Цели прототипа (проверить концепцию):**
1. Прозрачность: каждое действие агента имеет видимую причину и артефакт.
2. Вмешательство: пользователь влияет на ход выполнения, downstream пересчитывается.
3. Воспроизводимость: прогон = детерминированная последовательность событий.
4. Управляемая автономия: режим «авто» (агент решает сам) / «ручной выбор» (агент ждёт пользователя).

**Не-цели (вне рамок прототипа):**
- продакшн-авторизация, мультипользовательность;
- полноценный оркестратор многоконтурных агентов;
- персистентная БД (история хранится в JSON-файле);
- оптимизация стоимости LLM-вызовов.

## 4. Пользователи

| Роль | Сценарий |
|---|---|
| Разработчик agent-систем | Отлаживает поведение агента, ищет точку расхождения плана и факта |
| Продакт/ревьюер ИИ-фич | Оценивает объяснимость и доверие к агенту до продакшена |
| Тестировщик концепции | Прогоняет сценарии в демо- и LLM-режимах, проверяет вмешательства |

## 5. Ключевые пользовательские сценарии

1. **Демо-прогон без LLM**: запустить сценарий «анализ данных», наблюдать адаптацию плана
   (v1→v2→v3), раскрыть инспектор узла, увидеть причину динамического узла.
2. **Прогон с LLM** (`z-ai-web-dev-sdk`): планировщик строит план, исполнитель выполняет шаги,
   супервайзер корректирует план, итоговый узел суммирует результат.
3. **Вмешательство**: пауза → переопределение output узла → автоматический пересчёт потомков
   (узлы помечаются «изм.», счётчик запусков растёт).
4. **Развилка решений (ручной режим)**: агент предлагает 3 стратегии с обоснованием →
   модалка выбора (≥50% ширины экрана) → выбор гасит альтернативные ветки («ветка не выбрана»),
   итоговый результат зависит от выбранной стратегии.
5. **Развилка решений (авто-режим)**: агент выбирает вариант сам и показывает рассуждение.
6. **Уточняющий агент (последовательная точность)**: размытый запрос «напиши пост» → агент
   анализирует каждый шаг и вставляет эмерджентные вопросы (формат → блоки контента → тон);
   пользователь видит метр «понимания задачи» (20% → 95%, «Размытый вектор» → «Узкий вектор»)
   и может принимать смешанные решения (несколько вариантов одновременно).
7. **Воспроизведение**: timeline-скраббинг по событиям, переключение версий v1/v2/v3,
   экспорт MD-отчёта с секцией «Развилки и решения».

## 6. Функциональные блоки

| Блок | Что входит |
|---|---|
| Движок агента | Планировщик, исполнитель, супервайзер, decision-механика; режимы demo/llm |
| Живой граф | React Flow: кастомные узлы, рёбра со статусной раскраской, MiniMap, зум/пан |
| Развилки решений | Узлы kind='decision', варианты+обоснование+превью, режимы auto/manual, домены вопросов, смешанный выбор |
| Уточняющий агент | Эмерджентные вопросы по результатам шагов, метр «понимания задачи» (certainty) |
| Инспектор узла | Модалка ≥50vw: вход/выход, причина, тайминги, override/retry, детали решения; полные тексты без обрезки |
| Timeline | Курсор воспроизведения, play, Live-режим, тики decision-событий |
| История | Список прогонов, загрузка snapshot, удаление, режим решений при запуске |
| Аудит | Event-log, MD-экспорт отчёта, логи kinds: plan/adapt/control/intervention/decision |

## 7. Метрики успеха прототипа

- E2E-прогон всех сценариев без ошибок консоли (выполнено: 0 errors / 0 warnings).
- Задержка визуализации решения о выборе ветки — мгновенная (один tick event-stream).
- Вмешательство и выбор ветки находят отражение в экспортном отчёте (аудит-полнота).
- Мобильная адаптация 390px без горизонтального скролла.

## 8. Риски

- Нестабильность LLM-JSON → закрыто repair-парсером и ретраями (см. [ADR-001](../adr/ADR-001-llm-sdk-wrapper.md)).
- Сессии воспроизведения при больших прогонах — поток событий растёт; для прототипа принято
  как ограничение.
