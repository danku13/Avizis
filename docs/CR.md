## CR-001 (Task 1) — Старт: прототип TACG на z-ai-web-dev-sdk

**Мотивация.** «спланируй концепцию прототипа с использованием z-ai-web-dev-sdk
для тестирования и начинай реализацию» — проверить концепцию прозрачного графа
вычислений агента из `upload/agent_graph.md`.

**Изменения.**
- Создан mini-service `mini-services/tacg-agent/` (types, llm, demo, engine, store, index):
  планировщик → пошаговое выполнение → супервайзер-адаптация; пауза/стоп/резюм;
  override с пересчётом потомков; retry; история прогонов.
- Фронтенд: SVG-DAG канва, инспектор узла (правая колонка), тулбар, event-log,
  history-panel, timeline, zustand-стор, socket-клиент, fold событий.
- Тесты: `test-tacg-client.ts` (демо), `test-tacg-llm.ts` (реальный SDK).

**Результат.** Работающий стенд: живой граф + вмешательство + воспроизведение.
Исправлены при этом: graph:init не заполнял run.nodes; LLM-«reasoning» внутри массива
nodes (repair-JSON + ретраи); пауза не эмитила статус; прогресс считал skipped как done.

## CR-003 (Task 3) — Ветвления решений: «авто» / «ручной выбор» + мгновенная визуализация

**Мотивация.** «мне сейчас нехватает детализации там, где агент мог рассуждая принимать
одно из нескольких решений, при этом решение может влиять на финальный результат.
Я хочу видеть эти ветки и иметь возможность выбирать режим типа "авто"... или "ручной
выбор"... если выбор меняет набор дальнейших шагов, то требуется сразу визуализация».

**Изменения.**
- Модель: узел `kind='decision'` + `DecisionState`; варианты (label, rationale,
  nextSteps); все ветки в плане как цепочки с `branchOf`; итог зависит от хвостов веток.
- Движок: reasoning-фаза → offer; manual — ожидание на promise (`pendingDecision`),
  auto — `autoDecide` (демо-скрипт или LLM DECIDER); `resolveDecision` мгновенно гасит
  sibling-ветки (`discarded`); `setDecisionMode` на ходу (в т.ч. «агент решит сейчас»);
  stop/deleteRun — rollback; зависимости от discarded удовлетворены; прогресс по
  активным узлам.
- События/аудит: `decision:offer / decision:resolved / decision:mode`, лог kind
  'decision', секция «Развилки и решения» в MD-отчёте.
- UI: карточка-развилка (GitFork, fuchsia-пульс «ждёт вашего выбора», статус-строки),
  чипы веток A/B/C; `decision-modal.tsx` (≥50vw): вопрос, карточки вариантов с
  обоснованием и превью «дальше: …», «Принять вариант», тумблер Вручную/Авто; авто-открытие
  на offer; баннер ожидания в тулбаре; инспектор развилки (вопрос/варианты/кто решил/
  обоснование); event-log и status-badge дополнены; селект режима при запуске.
- Демо-сценарий: развилка «стратегия проверки аномалий» — A статистика / B глубокое
  расследование (2 шага) / C запрос у владельца; итог зависит от стратегии.

**Результат.** Развилки видны как ветки графа; в «ручном» агент ждёт пользователя,
в «авто» решает сам и показывает рассуждение; выбор мгновенно меняет набор дальнейших
шагов (гашение веток + пересчёт пути к итогу); playback показывает ветки до и после
решения. Тест `test-tacg-decision.ts` — 3 сценария пройдены; E2E без ошибок консоли.

## CR-004 (Task 5) — Уточняющий агент: эмерджентные вопросы, домены, смешанный выбор, метр понимания

**Мотивация.** «нужно, чтобы агент анализировал все входящие данные на каждом этапе на потребность
принятия дополнительных решений (расширение скоупа, специализация), задавал вопросы продуктового
и архитектурного порядка (разработка), уточнял tone of voice и формат (тексты) — последовательно
доходя до достаточной точности. Пользователь должен понимать, насколько агент "понимает" задачу
/ имеет узкий вектор решения. Пользователь может выбирать не только одно решение, но и смешанные».

**Изменения.**
- Типы: `DecisionDomain` (scope/specialization/product/architecture/tone/format/context/strategy),
  `DecisionState.selection 'single'|'mixed'`, `chosen: string[]`, `certaintyAfter`;
  `RunSnapshot.certainty` (0..1); события `decision:resolved.optionIds[]`, новое `run:certainty`.
- Движок:
  - `resolveDecision` принимает массив: валидация, для single — обрезка до одного; активируются
    ВСЕ выбранные ветки, гаснут остальные; аудит («смешанное решение агента/пользователя»).
  - `emitCertainty` — публикация самооценки «понимания задачи»; вызывается на старте, после
    каждого решения (`certaintyAfter`) и от супервайзера LLM.
  - `insertDecision` — эмерджентная развилка: узел-вопрос + ветки вариантов + перепривязка
    ещё не начатых узлов на хвосты веток (итог ждёт только реализованные ветки).
  - `maybeAdapt`: демо-сценарий «Напиши пост» вставляет 3 вопроса по ходу (формат → блоки
    [mixed] → тон); LLM-супервайзер получил режим `ask` (вопрос с вариантами) + оценку certainty,
    лимиты: не более 2 эмерджентных вопросов, не подряд с открытой развилкой.
  - Декайдер LLM: для mixed может вернуть несколько id; демо — скриптованные выборы по развилкам.
  - Планировщик LLM: возвращает начальную certainty и параметры развилок (domain/selection/
    certaintyAfter); sanitizePlan нормализует.
- Демо-сценарий «Напиши пост» (детект по ключевым словам задачи): размытый запрос →
  анализ → динамические вопросы формата/блоков/тона → черновик, собранный из выбранных
  параметров; certainty 0.2 → 0.45 → 0.75 → 0.95.
- Socket API: `decision:resolve {optionIds: string[]}` (совместимость с одиночной строкой).
- Фронтенд:
  - decision-modal: multi-select (переключение карточек), бейджи домена и типа выбора,
    «Принять смешанное решение (N)», подвал «понимание: 25% → ~70%».
  - run-toolbar: метр «Понимание задачи» (Размытый вектор <35% / Вектор сужается <70% /
    Узкий вектор ≥70%, цвет amber→emerald, чип «ждёт уточнений: N», тултип); отчёт MD:
    домены, mixed-итоги, строка certainty.
  - graph-canvas: «смешанное: A + B» в карточке, рёбра выбранного массива, «в составе»-бейджи.
  - node-inspector: домен уточнения, выбранные варианты «в составе», «смешанное решение «a + b»».
  - fold: `run:certainty` → RunView.certainty; совместимость со старыми прогонами (chosen-строка
    нормализуется в массив).
- Тесты: `test-tacg-decision` переведён на массивы (4/4); новый `test-tacg-clarity` — 17/17
  (эмерджентные вопросы, смешанный выбор пользователя и агента, single-guard, certainty-цепочка);
  LLM-тест пройден (планировщик сам строит развилку «Формат обзора»).
- E2E: авто-открытие модалок вопросов, смешанный выбор 2 блоков, метр 20→95% «Узкий вектор»,
  инспектор смешанного решения, мобильная 390px без переполнения, консоль 0/0, lint чист.

**Результат.** Агент последовательно уточняет размытый запрос вопросами с обоснованием
(домены: формат/объём/тон — или продуктовые/архитектурные в LLM-режиме); пользователь видит
«сколько агент понимает» (метр понимания с качественной шкалой) и может принимать как
одиночные, так и смешанные решения; выбор мгновенно меняет набор дальнейших шагов; вся
история переоценок — в event-stream и MD-отчёте.
