# FR-6xx — История и журнал

> Блок требований: история прогонов, журнал событий, аудит структурных усечений и использования токенов.
> Связанное: [ADR-002](../adr/ADR-002-socket-io-mini-service.md), [ADR-013](../adr/ADR-013-truncation-audit.md), [ADR-015](../adr/ADR-015-token-usage.md)

- **FR-601 (M) ✅** Список прогонов (задача, режим, статус, прогресс, узлы/динамика);
  загрузка прогона в воспроизведение; удаление.
- **FR-602 (M) ✅** Event-log с kinds: план, старт/финал узла, ошибка, адаптация,
  контроль, вмешательство, решение (fuchsia), прогон, инфо.
- **FR-603 (M) ✅ (CR-008)** Аудит усечений плана — ни одна структурная потеря не остаётся
  тихой: усечение узлов плана >12 (с перечислением отброшенных), зависимостей узла >5,
  вариантов развилки >4, шагов ветки >3, деградация «развилки» с <2 вариантами в обычный шаг,
  фильтрация `dependsOn`-ссылок на необъявленные узлы — каждая запись в журнале запуска
  (kind «лимит») с деталями N→M и идентификаторами; формат `N→M`, видимость в playback и
  MD-отчёте.
- **FR-604 (M) ✅ (CR-008)** Аудит усечений при адаптации: варианты >4 и шаги >3 в ask-вопросе
  супервайзера, усечение зависимостей >12 при перепривязке узлов на хвосты веток эмерджентной
  развилки — записи того же формата.
- **FR-605 (M) ✅ (CR-009)** Аудит использования токенов LLM (ADR-015): каждый успешный вызов —
  событие `llm:usage` (роль, опционально узел, вход/выход); сводка по запуску — totals +
  разбивка по ролям (планировщик/исполнитель/супервайзер/решатель) + число вызовов; атрибуция
  узлам (исполнитель — шагам, решатель — развилкам, с суммированием при повторных запусках);
  видимость: чип в тулбаре с тултипом по ролям, строка токенов в инспекторе узла, хвосты
  «· токены: ↑N / ↓M» в записях журнала шагов/плана, итог в финальной записи и summary,
  секция «Использование токенов» и колонка графа в MD-отчёте; live И replay (свёртка до
  курсора); демо-режим без LLM не порождает данных о токенах; если провайдер не сообщает
  usage — поля не появляются (цифры не выдумываются).
