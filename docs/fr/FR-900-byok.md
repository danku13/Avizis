# FR-9xx — BYOK: свои LLM-провайдеры и ключи

> Блок требований: роутер LLM-вызовов, конфигурация по ролям, безопасное хранение ключей,
> provenance моделей, UI настроек. Реализация — [CR-007](../cr/CR-007-byok-mvp.md).
> Связанное: [ADR-012](../adr/ADR-012-byok-llm-router.md)

- **FR-901 (M) ✅ (CR-007)** Роутер LLM-вызовов с адаптерами: `zai` (дефолт — поведение без
  конфигурации не отличается от текущего) и `openai-compatible` (baseUrl + apiKey + model;
  покрывает OpenAI, DeepSeek, OpenRouter, Groq, Ollama, LM Studio, vLLM). extractJson/repairJson,
  таймауты и ретраи — провайдер-агностичны, над адаптерами.
- **FR-902 (M) ✅ (CR-007)** Конфигурация по ролям: planner / executor / supervisor / decider —
  каждая роль резолвится по цепочке «роль → дефолт → zai»; параметры: adapter, baseUrl, model,
  apiKey, temperature. Для headless — env-переменные `TACG_LLM_*` (бутстрап без файла).
- **FR-903 (M) ✅ (CR-007)** Безопасность ключей: хранение только в серверном
  `data/llm-config.json` (chmod 600); API чтения возвращает маску (первые 3 + последние 4
  симв.), полный ключ не возвращается никогда; сохранение сопровождается валидацией пробным
  запросом; **ключи не появляются в `runs.json`, снапшотах, событиях, логах и экспортах** —
  гарантируется автоматическим тестом (поиск строки ключа в артефактах прогона).
- **FR-904 (M) ✅ (CR-007)** Provenance моделей: `RunSnapshot.llm = {role → {adapter, model}}`
  (без ключей) при старте прогона; `node.llm = {adapter, model}` у каждого LLM-узла; запись в
  журнал при старте планирования («Планировщик: openai-compatible · gpt-4o»); бейдж модели в
  инспекторе узла; индикатор активного провайдера в тулбаре; секция моделей в MD-отчёте. Replay
  показывает, какой моделью получен каждый узел.
- **FR-905 (M) ✅ (CR-007)** UI настроек: модалка (пресет провайдера, baseUrl, модель, ключ с
  show/hide, кнопка «Проверить подключение» с результатом, per-role overrides в расширенном
  режиме, сохранение); индикатор активного провайдера в тулбаре запуска.
- **FR-906 (S) ✅ (CR-007)** Диагностика ошибок провайдера: структурные ошибки (401 — неверный
  ключ, 404 — неверный baseUrl, недоступность, таймаут) отображаются человекочитаемо в модалке
  настроек и попадают в журнал прогона; LLM-прогон не падает молча — узел завершается ошибкой
  с причиной.
- **FR-907 (C) ⬜ задел** Нативные адаптеры anthropic / google-gemini, счётчики токенов и
  стоимости по узлам и прогону, стриминг ответов исполнителя (см. «не в MVP» в ADR-012).
