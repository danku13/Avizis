# Документация TACG Playground

> Корневой индекс документации. Структура оптимизирована для агентной разработки:
> каждый тип документа — своя папка, каждый документ — отдельный файл, в каждой папке — индекс.

## Карта документации

| Папка | Тип документа | Назначение | Индекс |
|---|---|---|---|
| [`prd/`](./prd/) | PRD | Продукт: проблема, цели, пользователи, сценарии, метрики | [prd/index.md](./prd/index.md) |
| [`product/`](./product/) | PRODUCT | Продуктово-рыночные документы: возможности, гипотезы рынка, VPM, ЦА | [product/index.md](./product/index.md) |
| [`adr/`](./adr/) | ADR | Архитектурные решения: контекст → решение → альтернативы → последствия | [adr/index.md](./adr/index.md) |
| [`fr/`](./fr/) | FR | Функциональные требования со статусами реализации | [fr/index.md](./fr/index.md) |
| [`cr/`](./cr/) | CR | Журнал изменений: мотивация → изменения → результат | [cr/index.md](./cr/index.md) |

## Порядок чтения (для человека и агента)

1. **Быстрый контекст продукта** → [`prd/PRD.md`](./prd/PRD.md) (5 минут).
2. **Что уже умеет стенд** → [`fr/index.md`](./fr/index.md) (таблица статусов) → конкретный `fr/FR-*.md`.
3. **Почему так устроено** → [`adr/index.md`](./adr/index.md) → конкретный `adr/ADR-*.md`.
4. **Как это появилось / что менять дальше** → [`cr/index.md`](./cr/index.md) → `cr/CR-*.md` (хронология сессии).
5. **Что это значит для рынка** → [`product/PRODUCT-001-capabilities-market.md`](./product/PRODUCT-001-capabilities-market.md)
   (возможности, гипотезы, VPM, 4 ЦА).

## Конвенции для агентной разработки

- **Один документ — один файл.** Имена: `kebab-case` латиницей, префикс-тип и номер:
  `ADR-007-auto-manual-decision-modes.md`, `FR-400-decisions.md`, `CR-003-decision-branches.md`.
- **Нумерация сквозная внутри типа** и не переиспользуется: новый ADR — `ADR-011+`, новый CR — `CR-006+`,
  новые FR — в пределах блока-сотни (например, `FR-309` в блоке инспектора `FR-3xx`).
- **Каждая папка содержит `index.md`** — таблицу документов (id, название, статус, дата).
  При добавлении документа — обновить индекс папки и этот README, если меняется карта.
- **Статусы**: ADR — `принято`; FR — `✅ реализовано` / `⬜ задел`; CR — соответствуют Task ID из `worklog.md`.
- **Что писать куда**:
  - продуктовая идея/сценарий → PRD (раздел «Ключевые пользовательские сценарии»);
  - новое архитектурное решение с альтернативами → новый ADR;
  - новое требование или уточнение существующего → FR (новый номер в нужном блоке);
  - зафиксированная правка по запросу пользователя/ревью → новый CR с цитатой мотивации.
- **Язык** — русский; кодовые идентификаторы, имена файлов и API — латиница.

## Реализация

- Движок: `mini-services/tacg-agent/` (bun + socket.io :3003, z-ai-web-dev-sdk, режимы demo/llm).
- Фронтенд: `src/components/tacg/` (React Flow граф, модалки инспектора/выбора, тулбар, timeline),
  `src/lib/tacg/` (типы, сокет-клиент, fold), `src/store/tacg-store.ts`.
- Тесты: `scripts/test-tacg-{client,llm,decision,clarity,byok,truncation,usage}.ts`; E2E-скриншоты: `scripts/tacg-*.png`.
- Рабочий журнал агентов: `/home/z/my-project/worklog.md` (вне репозитория — локальный артефакт сессии).
