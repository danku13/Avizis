# Документация TACG Playground

> Корневой индекс документации. Структура оптимизирована для агентной разработки:
> каждый тип документа — своя папка, каждый документ — отдельный файл, в каждой папке — индекс.

## Карта документации

| Папка | Тип документа | Назначение | Индекс |
|---|---|---|---|
| [`prd/`](./prd/) | PRD | Продукт: проблема, цели, пользователи, сценарии, метрики | [prd/index.md](./prd/index.md) |
| [`product/`](./product/) | PRODUCT | Продуктово-рыночные документы: возможности, гипотезы рынка, VPM, ЦА | [product/index.md](./product/index.md) |
| [`adr/`](./adr/) | ADR | Архитектурные решения: контекст → решение → альтернативы → последствия | [adr/index.md](./adr/index.md) |
| [`fr/`](./fr/) | FR | Функциональные требования со статусами реализации | [fr/index.md](./fr/index.md) |
| [`cr/`](./cr/) | CR | Журнал изменений: мотивация → изменения → результат | [cr/index.md](./cr/index.md) |

## Порядок чтения (для человека и агента)

1. **Быстрый контекст продукта** → [`prd/PRD.md`](./prd/PRD.md) (5 минут).
2. **Что уже умеет стенд** → [`fr/index.md`](./fr/index.md) (таблица статусов) → конкретный `fr/FR-*.md`.
3. **Почему так устроено** → [`adr/index.md`](./adr/index.md) → конкретный `adr/ADR-*.md`.
4. **Как это появилось / что менять дальше** → [`cr/index.md`](./cr/index.md) → `cr/CR-*.md` (хронология сессии).
5. **Что это значит для рынка** → [`product/PRODUCT-001-capabilities-market.md`](./product/PRODUCT-001-capabilities-market.md)
   (возможности, гипотезы, VPM, 4 ЦА).

## Конвенции для агентной разработки

- **Один документ — один файл.** Имена: `kebab-case` латиницей, префикс-тип и номер:
  `ADR-007-auto-manual-decision-modes.md`, `FR-400-decisions.md`, `CR-003-decision-branches.md`.
- **Нумерация сквозная внутри типа** и не переиспользуется: новый ADR — `ADR-011+`, новый CR — `CR-006+`,
  новые FR — в пределах блока-сотни (например, `FR-309` в блоке инспектора `FR-3xx`).
- **Каждая папка содержит `index.md`** — таблицу документов (id, название, статус, дата).
  При добавлении документа — обновить индекс папки и этот README, если меняется карта.
- **Статусы**: ADR — `принято`; FR — `✅ реализовано` / `⬜ задел`; CR — соответствуют Task ID из `worklog.md`.
- **Что писать куда**:
  - продуктовая идея/сценарий → PRD (раздел «Ключевые пользовательские сценарии»);
  - новое архитектурное решение с альтернативами → новый ADR;
  - новое требование или уточнение существующего → FR (новый номер в нужном блоке);
  - зафиксированная правка по запросу пользователя/ревью → новый CR с цитатой мотивации.
- **Язык** — русский; кодовые идентификаторы, имена файлов и API — латиница.

## Реализация

- Движок: `mini-services/tacg-agent/` (bun + socket.io :3003, z-ai-web-dev-sdk, режимы demo/llm).
- Фронтенд: `src/components/tacg/` (React Flow граф, модалки инспектора/выбора, тулбар, timeline),
  `src/lib/tacg/` (типы, сокет-клиент, fold), `src/store/tacg-store.ts`.
- Тесты: `scripts/test-tacg-{client,llm,decision,clarity,byok,truncation,usage,pricing,currency,openrouter-gate}.ts`; E2E-скриншоты: `scripts/tacg-*.png`, `scripts/e2e-gate-*.png`.
- Сборка exe движка: `bash scripts/build-executables.sh` (bun compile, 4 таргета, ADR-017).
- Десктоп: `src-tauri/` (Tauri v2, ADR-018); CI `.github/workflows/desktop.yml` — артефакты на push, релиз по тегу `v*` (доставка workflow-файла при PAT без scope workflow — `scripts/push-workflow-via-git-api.py`).
- Рабочий журнал агентов: `/home/z/my-project/worklog.md` (вне репозитория — локальный артефакт сессии).

- Полные тексты в инспекторе (Причина добавления / Вход / Выход — без обрезки) — `cr/CR-005`.
- Эмерджентные вопросы и объёмы текстов без жёстких лимитов; дисциплина объёма — в промптах
  (гигиена контекста) — `adr/ADR-011`, `cr/CR-006`, FR-808/809.
- BYOK-MVP: LLM-роутер (zai + openai-compatible), ключи в серверном конфиге с маскированием,
  provenance моделей в прогонах, модалка настроек — `adr/ADR-012`, `cr/CR-007`, FR-9xx.
- Аудит усечений: все структурные лимиты (узлы >12, зависимости >5, варианты >4, шаги >3)
  логируются в журнал запуска — «тихих потерь» больше нет — `adr/ADR-013`, `cr/CR-008`,
  FR-603/604.
- **Аудит токенов LLM** (вход/выход): по каждому шагу, по ролям и итогу запуска — чип в тулбаре,
  инспектор, журнал, MD-отчёт; live и replay — `adr/ADR-015`, `cr/CR-009`, FR-605.
- **Светлая/тёмная тема** (переключатель, запоминание, без всплеска) и **разведена цветовая
  кодировка**: развилки — amber («ваш ход»), динамика — violet, ожидание — цинк — `cr/CR-009`,
  FR-706/707.
- **Продуктово-рыночный документ**: возможности прототипа, 10 гипотез рынка/продукта,
  value proposition map, 4 ЦА — `product/PRODUCT-001`.
- **Максимум места графу**: журнал событий сворачивается в строку 44px с превью последней
  записи (выбор запоминается), шапка — компактная строка h-11 со статусом движка, темой и
  LLM-чипом BYOK (перенесён из тулбара) — `cr/CR-010`, FR-708.
- **Стоимость прогонов в USD поверх токенов** — динамический прайсинг: цены подтягиваются
  в рантайме с OpenRouter и из каталога LiteLLM (не захардкожены), кэш на диске (TTL 24 ч),
  ручной override в настройках; `≈$` по шагам, ролям и итогу — чип, инспектор, журнал,
  MD-отчёт с provenance прайсов — `adr/ADR-016`, `cr/CR-011`, FR-908.
- **Однофайловые исполняемые файлы движка**: `bun build --compile` (Windows/macOS/Linux,
  кросс-компиляция из любого окружения), портативные данные рядом с exe; рецепт полного
  «одного файла» (статический экспорт Next.js + встраивание) — `adr/ADR-017`.
- **Десктоп-приложение Tauri (единый exe с UI)**: статический Next.js вшит в бинарник, движок —
  sidecar-процесс на свободном порту 127.0.0.1 (гасится при выходе), данные — в каталоге
  приложения ОС; CI GitHub Actions (windows-latest): артефакты на каждый push,
  NSIS-установщик `TACG_0.10.0_x64-setup.exe` + portable zip в релиз по тегу v* —
  `adr/ADR-018`, `cr/CR-012`.
- **Конвертация валюты стоимости**: курсы ЦБ РФ (официальный XML + JSON-зеркало) с фолбэком на
  open.er-api и ручным override, кэш (TTL 6 ч); базис аудита — USD, конвертация на отображении:
  чип «≈$0,0027 · ₽0,263», инспектор, MD-отчёт с источником и датой котировки; селектор валюты
  (дефолт ₽, 15 валют) — `adr/ADR-019`, `cr/CR-012`, FR-910.
- **Гейт OpenRouter «agentic harnesses»**: free-эндпоинты, доступные только агентным харнесам
  (пример — `thinkingmachines/inkling:free`), проходят автоматически — запрос с tools
  (`submit_final_answer`) по детекту ошибки, кэш per модель, `tool_calls` разворачиваются в
  текст; 4xx ключа/доступа — без ретраев (мгновенная ошибка) — `adr/ADR-020`, `cr/CR-013`, FR-911.
- **Мгновенная обратная связь запуска**: прогон попадает в историю при создании (не по
  терминальному статусу), статус/прогресс/узлы в записи — live; при планировании область графа
  показывает «Агент работает…»; ошибка прогона — тост с причиной; бейдж режима — реальная модель
  прогона — `cr/CR-013`.
- **Автообновление по GitHub Releases + portable** (ADR-021, CR-014, FR-709): приложение тихо
  проверяет `releases/latest` при старте (и по кнопке в футере); новая версия — тост с кнопкой
  «Обновить»: скачивание портативного zip с прогрессом, подмена файлов рядом с exe
  (движок → прочее → оболочка), автоперезапуск; история/ключи/настройки не трогаются; один
  механизм для установленной (NSIS) и portable-версии (zip + README, без установки); контракт
  обновления E2E-тестируется в браузере (`?update-mock=1`); ядро — крейт `updater-core`
  (11 юнит/интеграционных тестов).
