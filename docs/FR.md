# FR — Функциональные требования TACG Playground

> Нумерация FR-###. Статусы: ✅ реализовано и проверено (тест/E2E) в этой сессии.
> Приоритет: M (must) / S (should) / C (could — задел на будущее).

## FR-1. Запуск и режимы

- **FR-101 (M) ✅** Запуск прогона по задаче пользователя: `run:start {task, mode, decisionMode}`.
- **FR-102 (M) ✅** Режим `demo` — детерминированный сценарий без LLM: валидация →
  развилка (3 стратегии) → ветка → итог; выходы зависят от выбранной стратегии.
- **FR-103 (M) ✅** Режим `llm` — план/исполнение/адаптация/решения генерируются
  z-ai-web-dev-sdk (3 LLM-роли + decider), JSON ремонтируется и валидируется.
- **FR-104 (S) ✅** Выбор режима решений при старте прогона (вручную / авто) из панели истории.
- **FR-105 (M) ✅** Управление прогоном: пауза / резюм / стоп; пауза уважается в фазе
  рассуждения агента; статус пушится мгновенно.

## FR-2. Живой граф

- **FR-201 (M) ✅** Граф — DAG узлов-шагов: слоевой layout, React Flow, пан/зум,
  fitView, MiniMap, Controls.
- **FR-202 (M) ✅** Статусная кодировка узлов: pending / running (пульсация) / done /
  error / skipped / discarded («ветка не выбрана» — полупрозрачная серая карточка).
- **FR-203 (M) ✅** Динамические узлы (добавлены супервайзером): dashed-рамка, бейдж
  версии (v2), причина появления видна в инспекторе.
- **FR-204 (M) ✅** Рёбра со статусной раскраской: cyan+animated (running), emerald (done),
  violet (динамические), fuchsia-пунктир (к вариантам до выбора), серый пунктир
  (погашенные ветки).
- **FR-205 (C) ✅** Вершину нельзя перетащить/удалить/соединить (наблюдательный режим).

## FR-3. Инспектор узла

- **FR-301 (M) ✅** Открывается кликом по узлу как модалка шириной ≥50% экрана
  (sm:55vw / lg:58vw / xl:64vw), высота 86dvh, на мобиле ~92vw; закрытие Esc/фон.
- **FR-302 (M) ✅** Содержимое: описание, вход, выход, причина динамического узла, ошибка,
  тайминги (start/finish/duration), зависимости (кликабельные ссылки-чипы), бейджи
  «развилка · N вариантов» / «ветка X» / «изм.» / счётчик запусков.
- **FR-303 (M) ✅** Вмешательство из инспектора: переопределить результат узла (output)
  → потомки пересчитываются (пометка «изм.», runs++), погашенные ветки не воскресают;
  повторить узел (retry) при ошибке.
- **FR-304 (S) ✅** Для узла-развилки: вопрос, все варианты с выделением выбранного,
  «Решение принял: агент | пользователь», блок рассуждения/обоснования, кнопка
  «Открыть выбор варианта» (если развилка ещё ожидает).

## FR-4. Развилки решений и режимы

- **FR-401 (M) ✅** Агент, рассуждая, доходит до развилки: узел `kind='decision'`
  с вопросом и 2–3 вариантами; каждый вариант: label, rationale (обоснование:
  плюсы/минусы/цена), nextSteps (превью дальнейших шагов).
- **FR-402 (M) ✅** Режим `manual` («ручной выбор»): агент публикует `decision:offer` и
  замерает в ожидании; на фронте авто-открывается модалка выбора (≥50vw) с карточками
  вариантов; закрытие модалки скрывает окно, но не отменяет ожидание (баннер в тулбаре
  возвращает к выбору).
- **FR-403 (M) ✅** Режим `auto`: агент выбирает вариант сам (LLM-decider с JSON-ответом
  {optionId, reasoning} либо демо-скрипт) и публикует рассуждение.
- **FR-404 (M) ✅** Смена режима на ходу: тумблер в тулбаре / подвале модалки; при
  переключении «в ожидании» в авто — агент решает немедленно; смена логируется.
- **FR-405 (M) ✅** Мгновенная визуализация выбора: выбранная ветка активна (emerald-рёбра),
  sibling-ветки гаснут (`discarded`, серые карточки, тихие рёбра), итоговый узел ждёт
  хвост выбранной ветки; прогресс считается по активным узлам.
- **FR-406 (S) ✅** Остановка/удаление прогона во время ожидания разблокируют движок
  (rollback узла развилки в очередь).
- **FR-407 (S) ✅** Аудит решения: кто выбрал, что, почему; карточка развилки показывает
  «выбрано: label · агент|вы».

## FR-5. Воспроизведение и версии

- **FR-501 (M) ✅** Прогон = лента событий; timeline со скраббингом, play, тиками
  decision-событий, режимом Live (авто-следование за хвостом).
- **FR-502 (M) ✅** Чипы версий v1/v2/v3: воспроизведение состояния графа на момент
  версии; на v1 видны все ветки как ожидающие (погашено 0).
- **FR-503 (M) ✅** Записанный прогон воспроизводим покадрово; вмешательство доступно
  только в live-режиме (notice-подсказка).
- **FR-504 (S) ✅** Экспорт MD-отчёта прогона, включая секцию «Развилки и решения».

## FR-6. История и журнал

- **FR-601 (M) ✅** Список прогонов (задача, режим, статус, прогресс, узлы/динамика);
  загрузка прогона в воспроизведение; удаление.
- **FR-602 (M) ✅** Event-log с kinds: план, старт/финал узла, ошибка, адаптация,
  контроль, вмешательство, решение (fuchsia), прогон, инфо.

## FR-7. Нефункциональные

- **FR-701 (M) ✅** Вёрстка на всю ширину экрана: app-shell без прокрутки на десктопе
  (h-dvh + overflow-hidden), граф занимает всё доступное пространство; правая колонка
  инспектора убрана (модалка).
- **FR-702 (M) ✅** Мобильная адаптация 390px: колонки в стек, канва ≥380px, модалки
  ~92vw, без горизонтального скролла.
- **FR-703 (M) ✅** Чистая консоль: 0 ошибок / 0 предупреждений; lint без замечаний.
- **FR-704 (S) ✅** Тёмная тема целиком (React Flow Controls/MiniMap/атрибуция стилизованы).
- **FR-705 (C) ⬜** (задел) Мультивариантные прогоны «A/B веток» параллельно — вне прототипа.
