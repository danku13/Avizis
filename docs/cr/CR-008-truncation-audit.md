# CR-008: Аудит усечений — конец «тихим потерям» структурных лимитов

> Task ID: 10-b · Формат: мотивация (цитата) → изменения → результат.

**Мотивация (цитата запроса).** «(б) сначала починить „тихие потери“ лимитов — логировать все
усечения в журнал аудита» — после разбора реестра ограничений (задача 8): усечения плана
(узлы >12, зависимости >5, варианты >4, шаги ветки >3), деградация развилки с <2 вариантов,
фильтрация неизвестных `dependsOn` и усечение перепривязки >12 происходят молча — в аудите
невидимы, что противоречит концепции прозрачного вычисления.

**Изменения (план, спека для агента-исполнителя).**
- `mini-services/avizis-agent/plan-sanitizer.ts` (новый) — логика `sanitizePlan` выделена из
  `engine.ts` в чистую функцию: `sanitizePlanData(json) → {nodes, certainty, notes[]}`, где
  `notes` — структурированный список усечений (код, сообщение, N→M, затронутые id/заголовки).
- `engine.ts` — импорт санитайзера; каждая заметка → запись в журнал запуска (новый kind
  «лимит», бейдж в event-log, см. FR-603): усечение узлов плана с перечислением отброшенных,
  зависимостей >5, неизвестных ссылок dependsOn, вариантов >4, шагов ветки >3, деградация
  развилки <2 вариантов.
- `engine.ts` — усечения при адаптации (FR-604): ask-вопрос супервайзера (варианты >4,
  шаги >3) и перепривязка на хвосты веток (зависимости >12) — записи того же формата.
- Ярлыки title/label ≤60 и заголовок вопроса ≤40 остаются без журналирования
  (нормализация идентификаторов, ADR-011 п. 5).
- `scripts/test-avizis-truncation.ts` (новый) — юнит-тест чистого санитайзера на фикстуре
  сверхлимитного плана (15 узлов, 6 вариантов, 5 шагов, 6+ зависимостей, ссылки вперёд,
  развилка с 1 вариантом); интеграционная часть — прогон через мок-провайдер в режиме
  oversized-plan (scripts/mock-openai.ts из CR-007) с проверкой записей в журнале прогона.

**Результат (верифицировано независимо, задача 11).** `test-avizis-truncation` — **31/31**
(15 юнит-проверок фикстуры + 16 интеграционных через мок `MOCK_MODE=oversized`): все 6 типов
усечений плана детектируются и логируются с N→M и идентификаторами (узлы 15→12 с перечислением
отброшенных, неизвестные dependsOn, зависимости >5, варианты 6→4, шаги ветки 5→3, деградация
развилки <2 вариантов); в компактном валидном плане notes пусты. Записи — kind `limits`, бейдж
`[лимит]` (orange) в event-log, порядок в журнале: лимиты → итог плана; playback и MD-отчёт
наследуют записи автоматически (8× `**[limits]**` в «Хронологии» отчёта E2E-прогона).
Регресс: `test-avizis-decision` 3/3, `test-avizis-clarity` 17/17, `test-avizis-byok` 13/13,
`test-avizis-llm-auto` (реальный z-ai) — полный прогон; lint чист, новых ошибок tsc нет.
E2E agent-browser (:81): 24 узла на канве, журнал с 8 записями «Лимит плана:», мобильная 390px
без поломок; скриншоты `scripts/avizis-trunc-*.png`. Честное ограничение: записи «Лимит
адаптации» (перепривязка >12, ask-вопросы >4/>3) реализованы в коде, но автотестами не покрыты —
тестовые сценарии их не порождают (супервайзер-мок всегда отвечает no_changes); проверены
ревизией кода. Расширение сверх спеки: деградация «развилки без вопроса» тоже логируется.
