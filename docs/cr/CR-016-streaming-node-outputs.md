# CR-016 — Стриминг выхода исполнителя (узел пишет на глазах)

> Дата: 2026-10-21 · Статус: ✅ завершено · ADR: [ADR-023](../adr/ADR-023-streaming-ephemeral-events.md) ·
> FR: [FR-907](../fr/FR-900-byok.md) (стриминг; нативные адаптеры anthropic/gemini — задел)

## Запрос

> Продолжение по README-Roadmap («Streaming node outputs») и честному ограничению
> PRODUCT-001 §2.2: «Нет стриминга ответов исполнителя (узел „загорается" и ждёт целиком)».
> Ядро позиционирования — «отладчик с брейкпоинтами»: отладчик показывает выполнение
> В МОМЕНТЕ, а не после; живой граф, на котором агент «думает» на глазах (H5/H10).

## Что сделано

1. **Канон событий (ADR-023)**: новый `node:stream` — эфемерный снапшот стрима:
   `text` = ВЕСЬ накопленный текст на момент эмита (снапшот, не дельта). Канал —
   только socket `run:event`, МИМО `emitEvent`: событие не пишется в `events[]`
   запуска и в `runs.json` — аудит-трейл (MD-отчёт, журналы), replay и его
   семантика не меняются. Троттлинг ~350 мс на узел + обязательный финальный
   снапшот (flush) до `node:update(done)`.
2. **Слой LLM (`llm.ts`)**: `chatTextDetailedStream(sys, user, timeout, role, sink)`
   над обоими адаптерами. zai: `stream: true` → ReadableStream SSE (SDK отдаёт тело
   при `text/event-stream|text/plain`). openai-compatible: `chatCompletionsStreamRequest`
   (`stream: true` + `stream_options.include_usage` — usage финального чанка → ADR-015);
   гейт agentic-harness в стриминге НЕ обходится — при любом сбое (4xx, гейт, не-SSE,
   пустой поток, обрыв) тихий откат на обычный полный вызов с гейт-циклом: результат
   идентичен нестридовому пути, UI получает финальный текст одним снапшотом.
   `consumeSseStream` терпим к 200-inline-error (OpenRouter mid-stream) и не-JSON строкам.
3. **Движок (`engine.ts`)**: `emitStream` (троттлинг + flush, мимо истории);
   `llmExecute` — исполнитель теперь через `chatTextDetailedStream` со sink;
   `demoExecute` — стрим-симуляция: canned-текст шага нарезается на ~25-символьные
   куски и эмитится пропорционально времени шага — эффект «модель пишет» виден
   на демо-прогонах без реального LLM (демо-видео/питчи).
4. **Клиент**: `GraphNode.streamingText?` (эфемерное поле: только live-канал,
   затирается следующим `node:update`); `fold.ts` — кейс `node:stream`;
   `findNode` (инспектор) — стрим-снапшоты применяются к running-узлу ПОСЛЕ
   последнего `node:update` (найдено live-QA: инспектор брал узел из последнего
   `node:update` и не видел стрим; исправлено, replay-ветка не задета — в
   персистентной истории стримов нет).
5. **UI**: инспектор — блок «модель пишет… · N симв.» + живой `pre` с пульсирующим
   курсором ▌; бейдж узла «пишет · N симв.» вместо статичного «выполнение…»;
   EN: «the model is writing… · N chars» / «writing · N chars» (ADR-022, +2 ключа
   на локаль). Журнал событий не тронут (node:stream — не LogEntry).

## Тесты

- `scripts/test-avizis-stream.ts` — 9/9: (A) unit-fold — снапшот задаёт
  `streamingText`, `node:update(done)` чистит, финал свёртки НЕ зависит от
  стрим-событий (детерминизм replay); (B) live через мок openai-compatible с
  SSE (7-симв. дельты, 30 мс): каждый исполненный шаг получил снапшоты, последний
  снапшот == финальный `output`, рост монотонен, usage из стрима (111/42 × 3
  вызова) дошёл до `llm:usage` и инспектора, прогон completed; (C) демо —
  ≥3 снапшотов на шаг, монотонность; (D) `node:stream` отсутствует в `runs.json`.
- E2E live (agent-browser, 1440×900): живой glm-прогон — бейдж узла
  «writing · 9 chars» во время работы модели; демо-прогоны — инспектор с живым
  блоком: сэмплы DOM «the model is writing… · 24 → 72 → 120 chars» с растущим
  текстом и курсором (61 сэмпл), RU-локаль «модель пишет… · 72 → 120 симв.»,
  dark-тема; 0 ошибок страницы/консоли. Скриншоты `download/avizis-stream-01…05`.
- VLM-ревью скриншотов отложено: zai vision в 429 на момент прогона — DOM-сэмплы
  фиксируют состояние однозначно.

## Результат

- FR-907 наполовину закрыт: стриминг — ✅ (оба адаптера + демо-симуляция);
  нативные адаптеры anthropic / google-gemini — остаются заделом (C-приоритет).
- PRODUCT-001 §2.2: ограничение «нет стриминга» снято; README Roadmap — пункт
  «Streaming node outputs» выполнен.
- Аудит-инварианты целы: стоимость/токены считаются по факту вызова (usage из
  стрима или полного ответа), MD-отчёт и replay не изменились, «тихих потерь» нет.
