## Резюме для руководства

### Концепция продукта

Avizis — это парадигма взаимодействия человека с ИИ-агентом, при которой процесс выполнения задачи становится **полностью прозрачным, управляемым и воспроизводимым**. Пользователь видит не просто результат работы агента, а **живую карту его мышления** — от запроса до финального ответа.

### Ключевая ценность

| Ценность | Описание |
|----------|----------|
| **Прозрачность** | Пользователь понимает, как агент пришёл к результату |
| **Контроль** | Пользователь может вмешаться и скорректировать процесс |
| **Доверие** | Возможность проверить и воспроизвести любой шаг |
| **Эффективность** | Сокращение времени на отладку и исправление ошибок |

### Бизнес-модель

- **SaaS-подписка** для корпоративных клиентов
- **Freemium** для разработчиков и небольших команд
- **Enterprise** с лицензированием и кастомизацией

## Проблема и возможности

### Текущая боль пользователей

| Проблема | Как проявляется | Эмоция |
|----------|-----------------|--------|
| «Чёрный ящик» | Агент выполняет задачу, но пользователь не понимает как | Разочарование, недоверие |
| Невозможность вмешаться | Агент идёт по неправильному пути, а пользователь не может остановить | Беспомощность |
| Непредсказуемость | Один и тот же запрос даёт разные результаты | Фрустрация |
| Отсутствие аудита | Невозможно проверить, как было принято решение | Тревога (особенно в бизнесе) |
| Статичный план | Агент не адаптируется, когда обнаруживает новые шаги | Раздражение |

### Возможность рынка

- Растущий спрос на **explainable AI** в связи с регуляторными требованиями
- Потребность корпораций в **аудируемых ИИ-системах**
- Запрос разработчиков на **инструменты отладки агентов**
- Необходимость **доверия** к ИИ-системам для массового внедрения

## Целевые пользователи и персоны

### Персона 1: «Разработчик ИИ-агентов»

| Атрибут | Описание |
|---------|----------|
| **Роль** | Senior Developer / AI Engineer |
| **Контекст** | Строит агентов для внутренних задач компании |
| **Боли** | Не может отладить поведение агента; тратит часы на выяснение, почему агент принял неверное решение |
| **Мотивация** | Создать надёжных, предсказуемых агентов |
| **Критерий успеха** | Сократить время отладки на 70% |

> 💭 **Цитата:** «Я трачу больше времени на разбор, почему агент сделал что-то, чем на написание самой логики»

### Персона 2: «Бизнес-аналитик»

| Атрибут | Описание |
|---------|----------|
| **Роль** | Аналитик, использующий ИИ-агентов для анализа данных |
| **Контекст** | Работает с критически важными бизнес-данными |
| **Боли** | Не может объяснить руководству, как агент пришёл к выводу; боится ошибок в отчётах |
| **Мотивация** | Получать проверяемые результаты и объяснимые выводы |
| **Критерий успеха** | Уверенно презентовать результаты работы агента руководству |

> 💭 **Цитата:** «Мне нужно понимать, откуда взялась цифра в отчёте, иначе я не могу её использовать»

### Персона 3: «Аудитор / Комплаенс-офицер»

| Атрибут | Описание |
|---------|----------|
| **Роль** | Проверяет ИИ-системы на соответствие требованиям |
| **Контекст** | Финансовый сектор, фармацевтика, госсектор |
| **Боли** | Нет инструментов для аудита ИИ-решений; невозможно проверить процесс принятия решений |

| Атрибут | Описание |
|---------|----------|
| **Роль** | Проводит эксперименты с ИИ-агентами |
| **Контекст** | Академия или R&D отдел |
| **Боли** | Не может воспроизвести эксперимент; разные запуски дают разные результаты |
| **Мотивация** | Публикация результатов, требующая воспроизводимости |
| **Критерий успеха** | Точно повторить эксперимент и получить идентичный результат |

> 💭 **Цитата:** «Наука требует воспроизводимости, а мои агенты работают непредсказуемо»

## Ключевые пользовательские сценарии

### Сценарий 1: «Анализ данных с адаптацией»

**Контекст:** Бизнес-аналитик просит агента проанализировать данные о продажах

```
1. Пользователь: «Проанализируй данные о продажах за Q3 и найди аномалии»

2. Avizis показывает граф:
   [Загрузка данных] → [Поиск аномалий] → [Генерация отчёта]

3. Во время выполнения:
   - Узел [Загрузка данных] обнаруживает пропущенные даты
   - Avizis визуально добавляет новый узел [Валидация данных]
   - Пользователь видит: 🟣 «Добавлен шаг: Проверка диапазона дат»
   - Причина: «Обнаружены пропущенные значения в поле 'дата'»

4. Пользователь может:
   - Нажать на новый узел → увидеть детали
   - Остановить выполнение → скорректировать данные
   - Продолжить → агент адаптируется

5. Результат:
   - Отчёт с анализом
   - Полная история графа (3 версии: исходная + 2 с добавлениями)
   - Возможность воспроизвести для аудита
```

### Сценарий 2: «Отладка агента»

**Контекст:** Разработчик ищет ошибку в поведении агента

```
1. Проблема: Агент иногда возвращает неверный результат

2. Разработчик открывает Avizis:
   - Смотрит историю выполнений
   - Сравнивает два запуска: успешный и неуспешный
   - Видит: в неуспешном запуске агент пропустил шаг валидации

3. Действия:
   - Включает обязательную валидацию для этого типа задач
   - Настраивает алерт при пропуске критичного шага

4. Результат:
   - Проблема решена
   - Правило валидации сохранено для будущих запусков
```

### Сценарий 3: «Аудит ИИ-системы»

**Контекст:** Комплаенс-офицер проверяет ИИ-систему для отчёта регулятору

```
1. Запрос: «Покажите, как система приняла решение по клиенту X»

2. Avizis предоставляет:
   - Полную историю выполнения для конкретного запроса
   - Все шаги с входными/выходными данными
   - Все изменения плана с объяснениями
   - Возможность точного воспроизведения

3. Результат:
   - Полный аудит-трейл
   - Документ для регулятора
   - Уверенность в прозрачности системы
```

## Дорожная карта продукта

### Фаза 1: MVP (Месяцы 1-3)

**Цель:** Доказать ценность прозрачности

| Функция | Приоритет |
|---------|-----------|
| Базовая визуализация графа | Критично |
| Отображение прогресса выполнения | Критично |
| История выполнений | Важно |
| Простой экспорт отчёта | Важно |

**Критерии успеха:**
- 100 пользователей в бете
- NPS > 30
- 50% пользователей возвращаются в течение недели

### Фаза 2: Интерактивность (Месяцы 4-6)

**Цель:** Включить вмешательство пользователя

| Функция | Приоритет |
|---------|-----------|
| Пауза/возобновление выполнения | Критично |
| Инспекция узлов (вход/выход) | Критично |
| Модификация графа пользователем | Важно |
| Сравнение версий графа | Важно |

**Критерии успеха:**
- 30% сессий с вмешательством
- Снижение времени отладки на 50%
- 500 активных пользователей

### Фаза 3: Воспроизводимость (Месяцы 7-9)

**Цель:** Обеспечить полный аудит

| Функция | Приоритет |

| Timeline-навигация по истории | Важно |
| Diff-view между версиями | Важно |

**Критерии успеха:**
- 5 корпоративных клиентов
- 95% точность воспроизведения
- Прохождение первого аудита клиентом
